# Project Status

- Purpose: Public TegneSpil browser game with a local teacher portal and a staged cloud-save server.
- Run/open: Public demo at `https://augustolrik.github.io/tegnespil`; the old local portal is `Start klasse server.cmd` then `http://localhost:8787/online`. The separate cloud API is `https://tegnespil-api.augustolrik.workers.dev`.
- Current state: GitHub Pages starts with the Tutorial and shows online save/load through the deployed Cloudflare Worker plus D1 API for 4A-4D. The panel uses student name/initials and a 4-digit PIN. One permanent asset pipeline handles PhotoDrop URLs, local file selection and web imports: use only follows a successful Worker import; the Worker validates raster images, caps upload/pixel dimensions, converts to WebP with the Images binding, writes immutable content-addressed files to R2, and saves only `{ assetId }` or a built-in reference in version 3 game files. This covers backgrounds, figures, clues and Pro animation frames. The source URL is R2 metadata only. Production has the `tegnespil-assets` bucket, `ASSETS` and `IMAGES` bindings, and D1 migration `0002_assets` applied. Worker version `f10c8985-96e4-42d9-9150-55a52421ad7d` is deployed. `npm run upload:class-assets` has uploaded and registered 56 class-library entries from `Klasser/` through the same pipeline; the library route returns permanent asset references and the assets serve as WebP from R2. The storage guard reserves space before upload and stops new unique assets at 9.6 GB; deduplicated objects are only counted once. Production asset usage after the import is 16,378,604 bytes, leaving 9,583,621,396 bytes. Local verification imported a GIF, served WebP from R2, saved it as background/clue/Pro-frame and opened the same `assetId` again. The 25 automated tests cover a fresh client after the source URL disappears, rollback after import failure, missing assets, every source label, validation, quota, the storage cap and class libraries. The browser maintains an automatic IndexedDB local draft, including larger image games, before the tutorial is loaded. The online save controls are closed by default and game status can be folded in editor modes. Levels can be deleted while at least one remains, and the Pro editor retains its Pro route tools when adding or switching levels. Resetting a Pro game cleanly restarts its frame animation from frame one. The editor now has one fixed objective: point + monster + portaler. All older objectives are converted to that ruleset when opened.
- Blockers: The public online save/load panel still needs an end-to-end test from a real second student computer after the GitHub Pages deployment has finished. Local teacher-server access remains blocked by the school firewall policy.
- Next useful step: Open the published site on two computers and complete the documented test using a web image whose original URL is then unavailable. The editor labels the track image as “baggrund” in the top menu and in the class-server library; internal storage names remain compatible with existing games.
- Interface note: PhotoDrop has been removed from the image-import menu. Teachers can add local pictures to each class folder and use the class library when those folders are synchronised; direct web import remains available.
- Objectives: New levels can use exact points, point + monster, code and clues, or maths areas. The crystal/monster-only and portal choices are removed from the editor to avoid overlapping goal choices; existing games retain their saved objective rules.
- Default tutorial: A browser without an existing draft opens `Spil/Toturial_ny.dgm`. Its 17 unique images have been migrated to permanent R2 references, leaving the committed tutorial bundle at about 50 KB while preserving all seven levels.
- Server games: The online panel lists saved games for the selected class. Selecting one fills in the student name, while the existing four-digit PIN remains required before the game content can be opened. The same listing route is available on the local teacher server.
- Testing: `TEST_CHECKLIST.md` contains the manual acceptance test for gameplay, editor, Pro editor, pictures, class library, online save/load, permanent cloud assets and developer checks.
- Class-library sync: `cloud-server` has a fast default sync that reads the online library first and uploads only new class-image filenames. Use the `:all` script variant only when replacing an image while keeping its filename.
- Image imports: The server no longer limits image imports per hour. Images are still validated, processed to WebP, deduplicated and stopped at the 9.6 GB R2 storage ceiling.
- Music controls: The toolbar shows only `Indlæs MP3` until a music file is chosen. The selected file then appears in a compact fold-out control containing change, play, stop and volume controls.
- Online panel: Online save/load is displayed below the game canvas instead of inside the editor/status panel.
