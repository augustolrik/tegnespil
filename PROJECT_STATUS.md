# Project Status

- Purpose: Public TegneSpil browser game with a local teacher portal and a staged cloud-save server.
- Run/open: Public demo at `https://augustolrik.github.io/tegnespil`; the old local portal is `Start klasse server.cmd` then `http://localhost:8787/online`. The separate cloud API is `https://tegnespil-api.augustolrik.workers.dev`.
- Current state: GitHub Pages starts with the Tutorial and shows online save/load through the deployed Cloudflare Worker plus D1 API for 4A-4D. The panel uses student name/initials and a 4-digit PIN. The source now contains one permanent asset pipeline for PhotoDrop URLs, local file selection and web imports: client-side use only follows a successful Worker import; the Worker validates raster images, caps upload/pixel dimensions, converts to WebP with the Images binding, writes immutable content-addressed files to R2, and saves only `{ assetId }` or a built-in reference in version 3 game files. This covers backgrounds, figures, clues and Pro animation frames. The source URL is R2 metadata only. The existing `Klasser` library has 43 valid images (baner and figures across 4A–4D); `cloud-server/tools/upload_class_assets.mjs` uploads them through this same pipeline and registers class-specific library entries in D1. The public library route returns only permanent asset references. Local Worker verification imported a GIF, served WebP from R2, saved it as background/clue/Pro-frame and opened the same `assetId` again. Unit tests also cover a fresh client after the source URL disappears, rollback after import failure, missing assets, every source label, validation, quota and class libraries. The public deployed Worker has not yet been given its R2/Images bindings, so this source change is deliberately not live until the documented migration and deployment occur. The browser maintains an automatic IndexedDB local draft, including larger image games, before the tutorial is loaded. The online save controls are closed by default and game status can be folded in editor modes.
- Blockers: The active Cloudflare OAuth identity can deploy Workers and D1 but R2 is not enabled on the account (Cloudflare API code 10042); activation requires signing in to the Cloudflare dashboard. Once activated, production needs an R2 bucket named `tegnespil-assets`, an `ASSETS` R2 binding, an `IMAGES` binding, the `migrations/0002_assets.sql` D1 migration, Worker deployment and `npm run upload:class-assets`. The public online save/load panel still needs an end-to-end test from a real second student computer after that release. Local teacher-server access remains blocked by the school firewall policy.
- Next useful step: Sign in at the Cloudflare dashboard and activate R2, then create/bind the bucket and deploy; after deployment run the class asset upload and two-computer test with a web image after its original URL is unavailable.
