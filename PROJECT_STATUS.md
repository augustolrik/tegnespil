# Project Status

- Purpose: Public TegneSpil browser game with a local teacher portal and a staged cloud-save server.
- Run/open: Public demo at `https://augustolrik.github.io/tegnespil`; the old local portal is `Start klasse server.cmd` then `http://localhost:8787/online`. The separate cloud API is `https://tegnespil-api.augustolrik.workers.dev`.
- Current state: GitHub Pages starts with the Tutorial and shows online save/load through the deployed Cloudflare Worker plus D1 API for 4A-4D. The panel uses student name/initials and a 4-digit PIN. One permanent asset pipeline handles PhotoDrop URLs, local file selection and web imports: use only follows a successful Worker import; the Worker validates raster images, caps upload/pixel dimensions, converts to WebP with the Images binding, writes immutable content-addressed files to R2, and saves only `{ assetId }` or a built-in reference in version 3 game files. This covers backgrounds, figures, clues and Pro animation frames. The source URL is R2 metadata only. Production has the `tegnespil-assets` bucket, `ASSETS` and `IMAGES` bindings, and D1 migration `0002_assets` applied. Worker version `f10c8985-96e4-42d9-9150-55a52421ad7d` is deployed. `npm run upload:class-assets` has uploaded and registered 56 class-library entries from `Klasser/` through the same pipeline; the library route returns permanent asset references and the assets serve as WebP from R2. The storage guard reserves space before upload and stops new unique assets at 9.6 GB; deduplicated objects are only counted once. Production asset usage after the import is 16,378,604 bytes, leaving 9,583,621,396 bytes. Local verification imported a GIF, served WebP from R2, saved it as background/clue/Pro-frame and opened the same `assetId` again. The 25 automated tests cover a fresh client after the source URL disappears, rollback after import failure, missing assets, every source label, validation, quota, the storage cap and class libraries. The browser maintains an automatic IndexedDB local draft, including larger image games, before the tutorial is loaded. The online save controls are closed by default and game status can be folded in editor modes.
- Blockers: The public online save/load panel still needs an end-to-end test from a real second student computer after the GitHub Pages deployment has finished. Local teacher-server access remains blocked by the school firewall policy.
- Next useful step: Open the published site on two computers and complete the documented test using a web image whose original URL is then unavailable.
